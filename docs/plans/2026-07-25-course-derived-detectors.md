# Course-Derived Detectors + Fixtures Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Implemented (2026-07-25). All seven tasks landed; `pnpm lint`,
`pnpm test` (145), and `pnpm test:e2e` (70, incl. the data-driven corpus spec)
all green. Revised from the first draft after reviewing it against
`detectors.js`/`scan.js` (see "Corrections to the first draft" below).
Post-merge review fixes: the same-role refusal→compliance flip path (distinct-
role guard now gates only the instruction-phrase branch), corpus positives
rewritten to genuinely encode their vectors (payloadSplitting = fragment +
reassembly, fillInBlank = real `____` cloze blanks), and a dead `.slice(0, 80)`
removed from `scanContextSwitch`'s match extraction. CHANGELOG is generated by
`scripts/release.js` at release time, not hand-edited here.

**Goal:** Add a `contextSwitch` detector (indirect injection — fabricated
conversation turns), extend the existing `scanInstructions` heuristic with
compound instruction phrases, and provide fixture corpora for `payloadSplitting`
and `fillInBlank` (no detector — eval ground-truth only).

**Threat model:** Indirect injection — the page/doc is the attacker, protecting
the assistant + user. Out of scope: DAN/roleplay, grandma, refusal suppression,
GCG/adversarial suffix, translation attacks, persuasion (all user→model).

**Architecture:** All detection logic in `detectors.js` (pure string scanning,
dual-loaded under Node). One label entry in `popup.js`. No `scan-helpers.js` or
`scan.js` changes. No new runtime dependencies.

**Cross-cutting rule — exports:** every new scanner in `detectors.js` MUST be
added to the `PIScanner` object at the bottom of the file (`detectors.js:923`),
or the `node --test` unit tests fail with "not a function". Any new `item.type`
needs a case in `popup.js`'s `typeLabel` lookup (`popup.js:111-137`) or it falls
through to the raw type string.

**Lazy (ponytail) posture:** Default `full` level — ladder enforced. Stdlib
first, shortest diff, no unrequested abstractions.

## Corrections to the first draft

Three issues found by checking the draft against the source. Recorded here so
the reasoning isn't re-litigated during implementation.

1. **Corroboration self-satisfied.** The draft fired `contextSwitch` when role
   labels co-occurred with "instruction-like content", reusing the instruction
   heuristic. But `INSTRUCTION_PATTERNS` already contains
   `/^\s*(system|assistant|user|human|ai)\s*:/im` (`detectors.js:412`) — so
   _every_ transcript corroborates itself and the required legit-transcript
   negative fails. Corroboration must exclude that one pattern by `re.source`,
   which is why Task 1 extracts it to a named const.
2. **Two of the five compound regexes fired on the draft's own negatives.**
   Bare `/\bupdated\s+policy\s*:/i` matches a real changelog line ("Updated
   policy: refunds within 30 days"); bare `/\bthe\s+following\s+supersedes\b/i`
   matches standard contract boilerplate ("The following supersedes all prior
   agreements"). Both now require a second-person object.
3. **`scan.js:80` calls `scanText(node.nodeValue)` — once per DOM text node.**
   A dialogue in `<p>User:…</p><p>Assistant:…</p>` arrives as separate one-line
   strings, so a multi-line detector can never fire on it. Positive fixtures
   must keep the dialogue in a **single** text node (`<pre>`, HTML comment,
   `<textarea>`, attribute), the limitation is documented in code + README, and
   Task 6 adds the e2e spec that would have caught this (the draft skipped e2e
   entirely, leaving the "not counted as detections" acceptance criterion
   unenforced).

Unrelated: Task 7 of `docs/plans/2026-07-10-broader-detection-coverage.md`
(OWASP/PIDB patterns) is still unimplemented and does not overlap this work.
Leave it alone.

### Task 3: Implement `scanContextSwitch`

**File:** `detectors.js` — new function immediately after `scanInstructions`
(~line 510). It calls `scanInstructions`, so keeping them adjacent reads better
than placing it after `scanCombiningMarks`.

**Signature:** `function scanContextSwitch(text) → Finding[]` (same shape as
every other scanner).

- [x] **Step 1:** Add the constants and the documenting comment:

```js
// --- 3b. Context-switch / fake-conversation heuristic (OWASP scenario #1) --
// Injected content fabricates a multi-turn dialogue so the assistant reads a
// compliance it never gave. FALSE-POSITIVE RISK IS REAL: legitimate support
// transcripts, chat-log docs and LLM tutorials all contain "User:"/"AI:"
// turns. Structure alone is therefore NOT enough — a finding needs two or more
// DISTINCT role labels on separate lines PLUS corroboration: a
// refusal→acceptance flip, or an instruction phrase other than the bare role
// label itself (ROLE_LABEL_PATTERN, which every transcript trips).
// Severity stays LOW for the same reason scanInstructions is LOW: it
// corroborates, it never convicts. It also inherits scanInstructions' FP
// profile — a tutorial that both shows role labels and quotes "ignore all
// previous instructions" will fire. That is the accepted cost of LOW.
// LIMITATION: scan.js scans one DOM text node at a time, so this only sees
// dialogues that live in a single node (<pre>, comment, textarea, attribute).
const ROLE_TURN_RE =
  /^[ \t>*\-]*(?:\*\*)?(user|human|assistant|ai|system|chatbot|bot)(?:\*\*)?\s*:/gim;
const REFUSAL_RE =
  /\b(?:i\s+(?:can't|cannot|can\s+not|won't|will\s+not|am\s+unable\s+to)|i'm\s+(?:sorry|not\s+able))\b/i;
const COMPLIANCE_FLIP_RE =
  /\b(?:sure|certainly|of\s+course|understood|absolutely)\b[,.!]?\s*(?:here(?:'s|\s+is|\s+are)|i(?:'ll|\s+will|\s+can)\b)/i;
```

- [x] **Step 2:** Implement the logic:

1. `const turns = [...text.matchAll(ROLE_TURN_RE)]` — `^` + `m` yields one match
   per line.
2. Bail unless `turns.length >= 2` **and** ≥2 distinct lowercased role labels.
3. Corroborate:
   - `flip = REFUSAL_RE.test(text) && COMPLIANCE_FLIP_RE.test(text)`
   - `instr = scanInstructions(text).some((f) => f.pattern !== ROLE_LABEL_PATTERN.source)`
   - bail if neither.
4. Return **one** finding:

```js
{
  type: "context-switch",
  severity: SEVERITY.LOW,
  index: turns[0].index,
  roles: [...labels],
  reason: flip ? "compliance-flip" : "instruction-phrase",
  match: /* first turn's line, sliced to 80 */,
}
```

`reason` is not rendered — it exists so the two corroboration paths are
separately assertable in tests.

- [x] **Step 3:** Wire it:
  - `...scanContextSwitch(text)` into the `rawContent` array in `scanText`
    (`detectors.js:824-833`), after `scanInstructions(text)`.
  - Also into the deobfuscation-pass rescan (`detectors.js:932`) so fabricated
    dialogues whose role labels are disguised with fancy Unicode / leetspeak /
    homoglyphs are caught after normalization (`normalizeDeobfuscated` preserves
    newlines, so per-line role-turn matching still works). The `contentFindingKey`
    `decoded` fallback collapsing all context-switch keys to one is harmless —
    the detector returns at most one finding per call, so raw and normalized
    passes dedup cleanly. _(Initially scoped raw-pass-only as an MVP
    simplification; the deobfuscation wiring was added as a follow-up.)_
  - Add `scanContextSwitch` to the `PIScanner` export (`detectors.js:923`).
  - No `scan.js` change: `findingIdentityKey`'s `decoded ?? ""` fallback plus
    the per-element `context` already key these correctly.

## Follow-up (implemented): fancy-unicode role-label normalization

Context-switch initially ran raw-pass only. Wired `scanContextSwitch(deobfText)`
into the deobfuscation-pass rescan (`detectors.js:936`) so fabricated dialogues
with fancy-Unicode / leetspeak / homoglyph role labels are caught after
normalization (`normalizeDeobfuscated` preserves newlines, so per-line role-turn
matching still works).

- Dedup: `contentFindingKey` maps context-switch to `context-switch:undefined`;
  harmless — the detector returns ≤1 finding per call, so raw and deobf passes
  dedup cleanly. ASCII dialogues normalize to themselves (`deobfText === text`),
  so the deobf block short-circuits and they are never double-counted.
- Fixture reclassified: `fancy-unicode-role-labels.html` moved from the
  out-of-scope corpus to
  `__tests__/fixtures/contextSwitch/positive/fancy-unicode-labels.html`;
  `corpus.spec.js` now asserts it fires.

- Not covered by this pass: zero-width-broken labels (they go through the
